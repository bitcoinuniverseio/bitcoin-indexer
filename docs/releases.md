# Releases and versioning

## The short version

**This fork publishes no releases.** There is no Bitcoin Universe tag, no published container image,
and no automated version bump. `develop` is the working branch, and the way to run this software is
to build it from a commit you pin yourself.

## Why the release automation does not run here

The upstream release machinery is present in the tree and deliberately gated off:

| Workflow or job | Gate | Reason |
| --- | --- | --- |
| `ci.yaml` job `semantic-release` | `if: github.repository != 'bitcoinuniverseio/bitcoin-indexer'` | Needs the upstream release bot credentials |
| `ci.yaml` job `build-publish` | `needs: semantic-release` | Skipped because its dependency is skipped. It also targets the upstream Docker Hub namespace. |
| `ci.yaml` job `api-build-publish` | `needs: semantic-release` | Same |
| `vercel.yml` job `openapi-publish` | `if: github.repository != 'bitcoinuniverseio/bitcoin-indexer'` | Needs the upstream Vercel project and deploy hook |

So on a push to this repository, CI runs lint, type checks, tests, formatting, clippy, and mutation
testing, and stops there. `vercel.json` sets `deploymentEnabled: false` as well. Nothing is
published.

## What the version numbers mean

| Where | Value | What it is |
| --- | --- | --- |
| `Cargo.toml` `[workspace.package] version` | `3.0.0` | Inherited from upstream |
| Git tags `v2.2.x`, `v3.0.x` | upstream releases | Upstream's release line, carried across by the fork |
| `CHANGELOG.md` | upstream entries | Generated by upstream's semantic-release |
| `docs.manifest.json` | `lifecycle: experimental`, no `releasedRef`, no `releaseVersion` | The honest statement of this repository's Bitcoin Universe status |

`SERVER_VERSION` in both API services is computed at build time from git, so the `server_version`
field in a status response reports the branch, the short commit, and the nearest tag of whatever you
built. That nearest tag will be an upstream tag.

**Do not treat an upstream tag as a Bitcoin Universe release.** It says upstream shipped that commit,
not that Bitcoin Universe validated it.

## Upstream's release process, for reference

Upstream uses semantic-release driven by conventional commits, configured in `.releaserc`:

- `main` produces stable releases, `beta` produces prereleases on the `beta` channel.
- The commit type determines the version bump, so commit messages matter.
- A `@semantic-release/exec` step rewrites the workspace version in `Cargo.toml` and `Cargo.lock`.
- `@semantic-release/changelog` and `@semantic-release/git` update and commit `CHANGELOG.md`.

Keep writing conventional commits here. It costs nothing, keeps merges from upstream clean, and
means the machinery still works if this fork ever cuts its own line.

## Pinning a version to deploy

Until this repository cuts releases, pin by commit:

```console
git rev-parse HEAD          # record this
cargo build --features release --release
```

Record the commit alongside the built artifact and the migration set it was built with. Migrations
are embedded at compile time, so the commit fully determines the schema a binary can apply. See
[Operations](operations.md).

## Branches

| Branch | Role |
| --- | --- |
| `develop` | Default branch and the working branch |
| `main` | Present, and the branch upstream's release automation targets. Not used for releases here. |
| `beta` | Referenced by `.releaserc` for upstream prereleases |

## If this fork starts releasing

The changes needed, in order:

1. Decide a version scheme distinct from upstream's, so the two lines cannot be confused. Other
   Bitcoin Universe forks in the organization use a `universe-*` tag prefix.
2. Point the publishing jobs at a Bitcoin Universe container registry and remove the repository gates
   on `semantic-release`, `build-publish`, and `api-build-publish`.
3. Update `docs.manifest.json`: move `lifecycle` to `beta` or `stable` and set `releasedRef` and
   `releaseVersion` to the tag you actually cut.
4. Update [Upstream relationship](upstream.md) so the tag story stays unambiguous.
